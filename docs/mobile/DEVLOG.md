# ReadyClip development timeline

[Mobile changelog](CHANGELOG.md) · [Windows releases](https://github.com/colornhue/ReadyClip/releases)

Development versions below use the labels recorded in each session. Public Windows beta numbers follow the GitHub release tags. Session and release timestamps in the backfilled entries use UTC.

| When | Milestone | Evidence and verification |
| --- | --- | --- |
| Origin, date unknown | The original Python highlight extractor answered a rider’s editing question: which parts of a long recording are worth replaying? Audio peaks identified candidates, and padding kept the approach and follow-through. | Retrospective from the surviving Python engine. The first standalone script and its creation date have not been recovered. |
| 2026-11-24 | Windows V2 was already running when work began on V3. V3 added parallel processing, NVENC with CPU fallback, progress and ETA, revised audio detection and a CSV manifest. | Development session reported 143 events and 27 clips across ten files using two workers and NVENC. V2 feature details were not recorded. |
| 2026-11-24 | Windows V3.1–V3.2 fixed rescanning of the export folder and terminal progress display. Its 8-bit H.264 output did not preserve HDR. |
| By 2026-11-24 | The Windows V4 desktop app paired a PySide6 interface with a separate Python processing engine. V4.0.1 recorded a Python 3.15 compatibility fix and improved error diagnostics. | Desktop V4 README, VERSION.txt, app.py and readyclip_engine.py. Version numbers here identify desktop snapshots. |
| 2026-11-24 | Windows V4.0 used six workers to produce one montage, with optional four-minute parts, grading, motion blur and resource monitoring. | Engine smoke test passed. A 245-second montage split into 240.02- and 5.01-second parts. Qt launch was untested in that session. |

| 2026-11-24 | Windows V4.3.0 added 240 × 136 thumbnails and a fallback for GPU monitoring. V4.3.1 restored a missing system-status refresh method. | A generated JPEG and regression checks verified V4.3.0. | 2026-11-25 | Windows V4.4.1 corrected branding assets. V5.0.0 added persistent skins, previews from completed render segments, telemetry and installer build configuration. | 2026-11-25 | Windows V5.0.2 paired a revised interface with the V5.0.1 extraction engine. V5.0.3 supplied the portrait-output baseline for V5.1.0. Portrait master and split output matched V5.0.3 frame for frame, with matching decoded audio. |
| By 2026-11-25 | Windows V5.1.1 appeared in a running-app screenshot with Factory Orange, render preview, waveform and telemetry. | The screenshot shows six audio events merged into two moments. It establishes the displayed version only. |
| 2026-11-25 | Windows V5.2.0 used keyframe-aware cuts and hardware encoding with CPU fallback. V5.2.1 verified lossless encoding of processed frames. | NVIDIA and CPU portrait masters and parts decoded in V5.2.0. AMD and Intel paths were untested in that session. All 30 decoded frames of the V5.2.1 portrait test matched their processed inputs byte for byte. |
| 2026-11-25 | Windows 0.5.0 beta bundled Python, Qt, FFmpeg and FFprobe in a portable build. | Session checked the bundled encoder list. Installer and full installation-cycle tests were pending. |
| 2026-11-25 | Windows 0.5.1 beta shipped local highlight detection, file and folder import, adjustable timing, lossless or hardware-assisted export and optional four-minute parts. | First [public Windows beta](https://github.com/colornhue/ReadyClip/releases/tag/v0.5.1-beta). | 2026-11-25 | Windows 0.5.2 beta removed the version banner from the app header. The release included waveform and rendered previews, color presets, frame blending, four skins and live resource statistics. | [Windows release and x64 MSI](https://github.com/colornhue/ReadyClip/releases/tag/v0.5.2-beta). The session checked the header in two skins and matched the download SHA-256 to the local installer. The [deployment workflow fix](https://github.com/colornhue/ReadyClip/commit/332ed537de5c43a036e68d2ec3a87f8464c3797a) made deployment wait for the site artifact. |
| 2026-11-25 to 2026-11-26 | The phone workflow grew from detecting individual moments into reviewing shots, shuffling reels, choosing a skin and saving or sharing an export. | 2026-11-25 to 2026-11-26 | Android and iOS 0.1.0 shared a one- to four-minute Randomize target. Shot removal updated duration and preview. |
| 2026-11-26 | Android 0.1.0 bounded queued frames in the earlier effects exporter. | Emulator preview remained active while blur changed. A four-minute graded reel exported with audio at 1882 × 1058 from a 2688 × 1512 source. This test predates the lossless-only APK below. |
| 2026-11-26 | The Android lossless test APK bundled a verified-copy path for complete supported MP4 files and a keyframe-aware path for compatible trims. Natural grade with motion blur off permits lossless export. | Android README and LosslessMp4.kt. The recorded host test checked a complete HDR file byte for byte. Simulated media I/O covered trims and rejection cases. On-device validation of this build remains open. |
| 2026-11-26 | The iOS test source added AVFoundation sample copying and output verification. Preview effects are available. Export requires compatible streams and cuts. | iOS README and ReadyMediaModule.swift. Xcode compilation, device playback and saving to Photos still need verification. |
| 2026-11-26 | Windows Vision Lab, an experiment based on 0.5.2, added audio and visual cues, activity profiles, Find Similar, a review queue, undo and saved reviews. Studio Preview tightened selection and addressed blank frames in Windows playback. | Vision Lab passed ten tests and exported five selections into a 45.55-second reel. The stricter detector selected 29 moments across 77 minutes (4.27% of the footage). Studio Preview checked the revised MP4 with a Windows decoder. |
| 2026-11-26 | A separate Windows landscape build combined the mobile-style interface with the desktop engine. The session checked layouts from 390 to 2560 pixels wide. |
| 2026-11-27 | The Windows development build added a lossless FFV1/MKV path, HDR metadata handling, tone-mapped previews, blur and Cool-grade fixes, animated status and reel details. ## Updating this log

Append a dated entry for each desktop, Android or iOS version change, implemented feature, fix or meaningful internal change, including changes between version bumps. Record the platform, what changed, why it mattered and what was actually verified. Link the commit, issue, build or release when available. Correct earlier entries when better evidence turns up. Add user-visible mobile changes to the mobile changelog in the same update.
